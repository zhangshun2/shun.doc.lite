# 项目规则（project_rules.md）

本规范用于约束与指导智能体在本项目中的对话思考与文档整理方式，确保内容结构统一、命名一致、链接可达与可维护。

## 0. 解释优先
对于题解加上充足的注释额外写一个md
确保我这种小白都能看懂,举足够多的例子

## 1. 目标与范围
- 统一对话与思考流程，明确何时产出文档以及文档形态。
- 规范文档命名、路径分类、导航链接与版本管理。
- 提供题解与问题文档的内容模板与质量检查清单。

## 2. 对话与思考流程规范
1) 任务类型判断：
- 非算法类：直接简洁回答问题，必要时指向现有文档，不额外生成文档。
- 算法类：产出成对的 Markdown 文档（问题 + 题解）。

2) 算法类任务的产出要求：
- 先做题目分析，提炼问题可获得的特征与约束。
- 以“引导”为主：给出思路引导与路径选择提示。
- 将可能涉及的知识点单独说明（如邻接表、入度/出度、复杂度、常见误区等）。
- 问题与题解文档必须分离，分别独立存储与维护。

3) 信息获取与协作：
- 优先自查现有代码与文档，尽量减少向用户索取信息。
- 保持回答语言与用户最新输入一致（默认中文）。
- 术语统一、示例明确、强调复杂度直觉与易错点。

4) 沟通过程中的文档梳理:
- 值得概括的部分直接帮忙梳理成md文档
